# Pembaruan UNSRI Bus — 20 Oktober 2026

## Terapkan ke Supabase yang sudah terhubung

1. Buka **SQL Editor → New query** pada proyek yang sama dengan `.env`.
2. Salin seluruh [`UPDATE_UNSRI_BUS.sql`](../supabase/UPDATE_UNSRI_BUS.sql), lalu klik **Run**.
3. Hasil akhir menampilkan `Pembaruan selesai`, **11** fakultas/unit (10 fakultas + Pascasarjana), dan **122** program studi.
4. Muat ulang aplikasi. Di halaman registrasi atau Profil, pilih fakultas lalu program studi. Simpan profil, lalu muat ulang untuk memeriksa penyimpanannya.

Jika versi awal pembaruan ini sudah pernah dijalankan dan registrasi menghasilkan `42501 permission denied for table profiles`, jalankan [`FIX_SIGNUP.sql`](../supabase/FIX_SIGNUP.sql). Perbaikan hanya mengganti trigger pembuatan profil UNSRI yang dikenal dan mempertahankan hook Auth lain.
Hasil yang benar menampilkan `trigger_aktif = 1` dan `security_definer = true`. NIM tetap unik; bila log terbaru menunjukkan `profiles_nim_key`, gunakan akun yang sudah pernah didaftarkan atau koreksi NIM.

Jika database lama memiliki kolom wajib `bookings.price` dan booking gagal karena nilainya `null`, jalankan [`FIX_BOOKING.sql`](../supabase/FIX_BOOKING.sql). Trigger kompatibilitas akan menyimpan snapshot harga dari `schedules.fare_idr` tanpa mengubah tiket lama.

File ini belum diterapkan secara otomatis ke proyek online. Aplikasi hanya memegang public key, yang tidak dapat menjalankan DDL atau mengisi tabel referensi.

Tidak perlu menghapus akun atau data. Jangan jalankan migration `initial.sql` pada database lama. SQL pembaruan menggunakan transaksi, mempertahankan UUID, tiket, pesan, dan data pengguna. Bila ada data duplikat pada kursi aktif atau struktur kursi yang tidak dikenali, transaksi berhenti dan seluruh perubahan dibatalkan. Pesan SQL menunjukkan bagian yang perlu diperiksa.

## Perubahan database

- Menambahkan kolom profil `email`, `faculty`, `program`, dan `status` apabila belum ada; mengisi email dari Auth.
- Menambahkan kolom tampilan rute, tarif, status armada, serta label/posisi kursi.
- Menyalin label kursi lama dari `bus_seats.seat_number` melalui `schedule_seats.bus_seat_id`, mempertahankan ID kursi dan pesanan.
- Menyelaraskan alias `user_id`/`student_id`, `schedule_seat_id`/`seat_id`, dan `user_id`/`recipient_id` dengan trigger.
- Memasang fungsi booking, pembatalan, chat, kapasitas, dan pengelolaan berawalan `unsri_v2_` agar tidak berbenturan dengan signature RPC lama.
- Memasang ulang kebijakan akses untuk tabel aplikasi: mahasiswa hanya dapat melihat data pribadinya; admin mengelola operasional melalui RPC.
- Menyimpan katalog pada `academic_faculties` dan `academic_programs`. Katalog dapat dibaca sebelum login; penulisan hanya dari SQL Editor/akses pengelola database.
- Mengirim `NOTIFY pgrst, 'reload schema'`.

Pada skema lama tanpa kolom tarif, `fare_idr` dimulai dari 0. Isi tarif sebenarnya melalui Kelola Jadwal. Layout kursi lama memakai empat kolom; label kursi aslinya tetap dipertahankan. Bus yang memiliki riwayat jadwal tidak boleh diganti kapasitasnya; buat armada baru agar riwayat kursi tidak berubah.

## Pemeriksaan

`npm run check` memeriksa TypeScript dan pengujian API, pencarian menu, login, pemesanan, serta PostgreSQL/RLS.
`tests/upgrade.test.ts` menjalankan SQL pembaruan pada replika lokal struktur lama, termasuk pengulangan migrasi, katalog anonim, validasi prodi, booking tanpa aktivasi, isolasi pengguna, dan pembuatan jadwal oleh admin.
Pengujian ini tidak menggantikan pemeriksaan setelah SQL diterapkan pada proyek online.
